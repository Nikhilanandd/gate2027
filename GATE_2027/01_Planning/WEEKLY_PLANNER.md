# GATE 2027 — Weekly Planner

## How to Use This Planner

1. **Every Sunday evening** (or Monday morning), set your weekly goals using the framework below.
2. **Every evening**, review progress and adjust tomorrow's plan.
3. **Every Sunday**, do a full weekly review — check off milestones, review error log, plan next week.

---

## Weekly Goal-Setting Framework

Use this checklist to set goals every week. Be specific — "study algorithms" is vague; "complete 20 questions on DFS/BFS and revise all graph algorithms" is actionable.

### Goal Categories

**A. Learning Goals (New Topics)**
- [ ] Topic 1: _________________ (subject, specific subtopic)
- [ ] Topic 2: _________________
- [ ] Topic 3: _________________
- Max 3 new topics per week. Quality > quantity.

**B. Practice Goals (Problem Solving)**
- [ ] PYQs solved: _____ / target: _____
- [ ] New concepts practiced: _____
- [ ] Speed improvement area: _________________

**C. Revision Goals**
- [ ] Formula sheets revised: _____ / target: _____

- [ ] Error log reviewed: Yes / No

**D. Mock / Test Goals**
- [ ] Full mock attempted: Yes / No
- [ ] Sectional test attempted: Yes / No
- [ ] Mock analysis completed: Yes / No

## Subject Rotation Strategy

### Principle: The 10-Day Cycle

All 10 subjects cannot be covered in a single week without burnout. Instead, use a **rolling 10-day cycle** where each subject gets dedicated attention every 10 days, while revision happens more frequently.

### Primary vs Secondary Allocation

| Priority | Subjects | Frequency | Hours/Week |
|----------|----------|-----------|------------|
| **Primary** (daily touch) | Engg Math, PDS, Algorithms, OS, DBMS | 5x/week | 12–15 |
| **Secondary** (3x/week) | CN, TOC, COA | 3x/week | 6–8 |
| **Tertiary** (2x/week) | Digital Logic, Compiler, GA | 2x/week | 4–6 |

### Weekly Subject Coverage Map

| Week Focus | Mon | Tue | Wed | Thu | Fri | Sat | Sun |
|------------|-----|-----|-----|-----|-----|-----|-----|
| **Hard Subject** | Engg Math | Algorithms | OS | Engg Math | Algorithms | — | — |
| **Medium Subject** | PDS | DBMS | CN | TOC | DBMS | — | — |
| **Light Subject** | GA | DL | GA | Compiler | COA | — | — |
| **Revision** | Prev day | Prev day | Prev day | Prev day | Prev day | All week | All week |

> Every subject appears at least once per week. Primary subjects get 4–5 slots. This prevents knowledge decay.

## Error Log Review Protocol (Sunday)

The error log is the most important document in your preparation. Review it every Sunday using this protocol:

### Step 1: Categorize Errors

| Error Type | Description | Action |
|------------|-------------|--------|
| **Concept Gap** | Didn't know the concept at all | Study the concept, add to formula sheet |
| **Misread Question** | Read it wrong or missed a detail | Practice careful reading, underline keywords |
| **Silly Mistake** | Knew it but got it wrong (calculation, etc.) | Slow down, double-check work |
| **Time Pressure** | Knew it but ran out of time | Practice speed, skip hard questions first |
| **Trick/Trap** | Question was designed to mislead | Note the trap pattern, add to "watch out" list |

### Step 2: Find Patterns

- Which error type appears most often? _________________
- Which subject has the most errors? _________________
- Which subtopic within that subject? _________________

### Step 3: Take Action

- [ ] Re-study the concept for all "Concept Gap" errors
- [ ] Create a "Common Traps" page in your notebook
- [ ] Add "Check: _________________" reminders for recurring silly mistakes
- [ ] Adjust next week's study plan to focus on weak areas

### Step 4: Rate Your Error Log Quality

| Metric | This Week |
|--------|-----------|
| Errors logged: | _____ |
| Errors reviewed: | _____ |
| Errors corrected: | _____ |
| Error log completeness: | _____% |
| Recurring errors identified: | _____ |

> **Target:** 100% error log completeness. Every wrong answer gets logged. No exceptions.
